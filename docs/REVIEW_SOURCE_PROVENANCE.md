# Source-linked final benchmark human-review evidence (v1)

**Status — November 4, 2026: BLOCKED. No human review has been submitted.** This protocol strengthens the 60-case review gate that must pass *before* a genuine base-vs-adapter GPU evaluation. It **cannot** determine whether the person named by a reviewer code exists, is competent in Norwegian/Arabic, acted independently, or produced semantically correct judgments.

## Why the gate was changed

Previously, the project would accept a signoff JSON containing `"review_complete": true`, the correct dataset SHA-256 and two arbitrary reviewer pseudonyms. That was **metadata, not source-linked review evidence**. Now `scripts.frozen_pair_inference` refuses to unlock from that claim alone. The gate requires 2–4 full reviewer CSV files, a separately generated reconciliation, SHA-256 checksums for every input, 60×3 affirmative judgments per reviewer, and explicit individual approval declarations. No review is generated by this software.

## Actual human workflow (private local files; do not commit)

1. With qualified reviewers, generate a **blank** independent packet for each real reviewer. Use pseudonyms, not personal names:

```bash
python -m scripts.review_holdout --export reviewer_A --output reviews/reviewer_A.csv
python -m scripts.review_holdout --export reviewer_B --output reviews/reviewer_B.csv
```

2. Each human separately examines all 60 fictional-policy questions, all candidate answers and source evidence, and the 3 review criteria (180 judgments per reviewer). Especially check Norwegian and Arabic translations, unsupported answers and adversarial instructions. **No model predictions should be available to the reviewers.** Do not fill these rows programmatically or on behalf of reviewers.

3. After each person finishes, reconcile the actual files:

```bash
python -m scripts.review_holdout \
  --summarize reviews/reviewer_A.csv reviews/reviewer_B.csv \
  --output reviews/reconciliation.json
```

The reconciliation must report `READY_FOR_MANUAL_ADJUDICATION_AND_SIGNOFF`, no missing fields, no disputes, no negative fields and 180 unanimous **yes** slots. If anyone judges a case `no`, **correct or replace the dataset** and issue a new version with a different SHA before inference; do not override a negative label to pass this gate. The current v1 source file is frozen and must not be rewritten after model evaluation.

4. Record the **exact SHA-256 bytes** for each final CSV and the reconciliation JSON:

```bash
sha256sum reviews/reviewer_A.csv reviews/reviewer_B.csv reviews/reconciliation.json
```

On Windows PowerShell:

```powershell
Get-FileHash reviews/reviewer_A.csv -Algorithm SHA256
Get-FileHash reviews/reviewer_B.csv -Algorithm SHA256
Get-FileHash reviews/reconciliation.json -Algorithm SHA256
```

**Optional private signoff draft (still unsigned):** After both real reviewers finish their CSVs and the reconciliation is unanimously affirmative, you can avoid manually copying the hashes by generating a local draft:

```bash
python -m scripts.prepare_review_signoff \\
  --review-csvs reviews/reviewer_A.csv reviews/reviewer_B.csv \\
  --reconciliation reviews/reconciliation.json \\
  --output reviews/signoff_draft.json
```

This checks the original source files and reconciliation, writes a **new private draft only**, and deliberately sets `review_complete: false`, every `approved: false`, every independence/blinding declaration to `false`, and competence lists to `[]`. It does **not** update the existing signoff or make any claim that people reviewed the benchmark. Actual humans must approve and fill the declarations themselves before the completed signoff can be placed in `docs/`.

5. After independent human adjudication and *actual* approval, manually populate the **existing** `docs/final_benchmark_review_signoff.json`, keeping the exact frozen benchmark hash. The example below is a **schema example with placeholders, not approval evidence**:

```json
{
  "review_complete": false,
  "dataset_file": "data/final_holdout_v1.jsonl",
  "dataset_sha256": "REPLACE_WITH_EXACT_64_CHARACTER_DATASET_SHA256",
  "reviewers": ["reviewer_A", "reviewer_B"],
  "review_evidence": {
    "schema": "policyproof_review_evidence_v1",
    "review_files": [
      {
        "reviewer_code": "reviewer_A",
        "path": "reviews/reviewer_A.csv",
        "sha256": "REPLACE_WITH_ACTUAL_REVIEWER_A_CSV_SHA256"
      },
      {
        "reviewer_code": "reviewer_B",
        "path": "reviews/reviewer_B.csv",
        "sha256": "REPLACE_WITH_ACTUAL_REVIEWER_B_CSV_SHA256"
      }
    ],
    "reconciliation": {
      "path": "reviews/reconciliation.json",
      "sha256": "REPLACE_WITH_ACTUAL_RECONCILIATION_SHA256"
    },
    "approvals": [
      {
        "reviewer_code": "reviewer_A",
        "approved": false,
        "independent_review_declared": false,
        "blinded_to_model_predictions_declared": false,
        "competent_languages": []
      },
      {
        "reviewer_code": "reviewer_B",
        "approved": false,
        "independent_review_declared": false,
        "blinded_to_model_predictions_declared": false,
        "competent_languages": []
      }
    ]
  }
}
```

**Do not change** `review_complete` or any reviewer approval flags to `true` merely to enable inference. Each reviewer must actually approve their independent work, including the fact that they did not see the model predictions. Only list languages for which they can competently assess translations. Across the reviewers, declared competence must cover `en`, `no` and `ar`. The code checks these declarations' format but **cannot certify** actual identity, education, fluency, independence or semantic correctness.

6. Run the new read-only, CPU-only check:

```bash
python -m scripts.verify_review_provenance
python -m scripts.frozen_pair_inference
```

The first command reports `BLOCKED` until genuine source review files, exact evidence hashes and a properly completed signoff all exist. It **does not train**, call a language model or alter the signoff. The paired runner also requires a separate, structurally validated real PEFT adapter and explicit GPU execution confirmations. A successful source-linked review proof **alone** never enables GPU work or indicates improved safety.

## Threat model and limitations

- Missing files, files outside the private `reviews/` directory, symlinked files, overly large evidence, incorrect hashes, changed proposed gold/context/IDs and incomplete case coverage are rejected.
- The validator **recomputes** the reconciliation from every CSV, and rejects disagreement or fake reconciliation content even if someone updates its declared SHA.
- It checks full `yes` judgments for evidence support, translation fidelity and question unambiguity on all cases; a blank or `no` cannot be overridden by writing a positive signoff.
- It checks distinct reviewer codes, matching per-review CSV codes and approval declarations, and declarative language coverage. It does not cryptographically authenticate who edited the CSVs. A malicious operator can fabricate entire packs and approvals; independent process governance is still necessary.
- `reviews/` is deliberately ignored by Git to avoid accidentally publishing personal/private feedback. Do not expose completed private reviewer CSVs or original human identities on the public Streamlit dashboard. Preserve privately in a controlled, backed-up archive for auditing with reviewer permission.
- Unit tests create **artificial all-yes CSV files in temporary directories** to exercise the safety gate. They are **not completed independent human review** and must never be submitted as research evidence.

The public synthetic 60-case candidate is not a secret, truly blind final evaluation. This software improvement tightens provenance consistency but cannot convert it into one.
