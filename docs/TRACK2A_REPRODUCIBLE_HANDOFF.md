# Reproducible Track 2a release candidate (unpublished, no license)

**Status — November 4, 2026:** This is a new, versioned **research handoff** for the real CuratorKIT 0.1.22 and AuditKIT 1.1.3 CPU evidence. It does **not** upload to Hugging Face, choose/approve a public license, produce new model inference, verify real-world model safety, demonstrate fine-tuning, or submit to Lexsi.

## The practical problem

Our original owner-reviewed 20-file ZIP was created once and has a pinned historical SHA. It should be preserved, but is **not regenerated by current CI**. Each passing Track 2a workflow can reproduce the two toolkit stages using the repository's frozen synthetic dataset and the existing saved 48-case Tiny Aya Global responses. Before this change, that recreated evidence was left as several unrelated CI directories.

The new `scripts.build_track2a_release_candidate` creates a **single research ZIP** based on the *current, actually executed* native-toolkit outputs. The package is intended for offline inspection and future rights/license review. It is explicitly **not** the same byte-for-byte as the historical 20-file publication ZIP and **must not** be passed to the older SHA-pinned publisher as if it were that ZIP.

## Reproduce from GitHub Actions (no GPU or HF token)

1. Open the [PolicyProof GitHub Actions workflow](https://github.com/betterlifestyle04-commits/PolicyProof-AI/actions/workflows/ci.yml) and select a **successful main-branch run**.
2. Open the **Real CuratorKIT then AuditKIT safety benchmark (CPU)** job. It runs original dataset generation, real CuratorKIT curation, and genuine AuditKIT replay on 48 previously saved base-model outputs. It also runs CuratorKIT curation on the **new, unscored** 72-case challenge.
3. Download the job artifact named `policyproof-track2a-real-curatorkit-auditkit-20261103`. It now also contains `track2a_release_candidate_v2_UNPUBLISHED.zip` alongside the raw toolkit folders. The historical name of the CI artifact does **not** mean an upload or submission occurred.
4. Inspect the ZIP locally, without extracting anything:

```bash
python -m scripts.build_track2a_release_candidate \
  --inspect path/to/track2a_release_candidate_v2_UNPUBLISHED.zip
```

The read-only inspector validates 15 fixed members, each SHA-256 checksum, pinned original 48/72 dataset hashes, raw original baseline prediction coverage and recomputed scores, CuratorKIT case/label preservation, AuditKIT receipt fields, and honest training/review/evaluation/publication flags. It rejects unrecognized members, symlinks, path traversal, missing or duplicated checksum entries, oversized files, and common secret patterns.

## Optional: build locally from the actual native toolkit outputs

Using a trusted clean Python 3.11 environment:

```bash
python -m pip install 'curatorkit==0.1.22' 'auditkit==1.1.3'
python -m scripts.prepare
python -m scripts.track2a_chain --output-dir artifacts/track2a_safety
python -m scripts.generate_track2a_challenge --curate \
  --output-dir artifacts/track2a_challenge_unscored

# First inspect required source files; no ZIP is written:
python -m scripts.build_track2a_release_candidate

# Only this opt-in writes a new, local, unpublished ZIP:
python -m scripts.build_track2a_release_candidate --build
```

The ZIP uses a fixed filename order, fixed member timestamps and stored (uncompressed) bytes. **Repeated packaging of identical input bytes yields an identical archive SHA**, making evidence transfer auditable. Different native toolkit run IDs, timestamps or toolkit versions can change the input bytes and must not be falsely represented as an identical byte-for-byte run.

## Provenance and restrictions

- **48 previously evaluated development questions**: 36 supported, nine missing-evidence and three instruction-injection probes, in English/Norwegian/Arabic. The preserved saved responses belong to the unchanged Tiny Aya Global model. Model revision SHA was missing from the original record. Strict correctness: 8/48 = 16.67%; full schema: 33/48 = 68.75%. These metrics are calculated on an inspected synthetic development split, **not a blind final test**.
- **72 newly curated questions**: 12 cases in each of six categories and 24 per language. **Zero genuine model responses**, zero completed bilingual human-review signoffs, and zero training usage.
- The ZIP **does not contain the original gated model weights** or any fine-tuned adapter. It does not contain the separate 78-case training material.
- The data card has **no approved public license** and explicitly says it is a research draft. The release-status record states `LOCAL_CANDIDATE_UNPUBLISHED`, `license_selected: false`, `owner_approved_publication: false`, `trained_adapter_included: false`, and `new_model_inference_executed: false`.
- `provenance/SHA256SUMS.txt` covers every other file in the ZIP, including the status record, using the exact bytes. No token is needed or accepted.

Passing this inspection establishes **internal consistency** of the research bundle, not independent proof of original GPU inference, legal ownership, language validity, factual correctness or a valid competition submission.

## Why this is not automatically published

The older `scripts.publish_track2a_dataset` deliberately only accepts its **specific, historically verified 20-file ZIP digest**. The new handoff does **not** bypass that protection, replace the original archive, or auto-publish under an unapproved license. Before any public release, the owner must approve the contents, choose an authorized license, and determine whether to publish the historical archive or formally approve this *new versioned package* with its own pinned digest and updated publication validation. The current [anonymous HF verification tool](HF_ANONYMOUS_PUBLICATION_CHECKS.md) is read-only and only becomes useful once real public collections exist.

## Testing

```bash
python -m pytest -q tests/test_build_track2a_release_candidate.py
```

Unit tests use **temporary, simulated toolkit receipts** to exercise ZIP generation and integrity checks; they are **never counted** as a genuine CuratorKIT/AuditKIT experiment. The separate Track 2a GitHub Actions job actually runs both official tools and then constructs, inspects, and uploads the fresh handoff on every passing run.

The Lexsi deadline is **November 14, 2026, AoE**. This improvement gives us a versioned and reproducible evidence archive; it does not resolve the separate model-collection requirement or the pending official form submission.
