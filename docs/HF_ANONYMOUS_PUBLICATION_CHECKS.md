# Anonymous Hugging Face publication verification (Track 2a)

**Status (November 4, 2026): BLOCKED.** The repository's [publication manifest](hf_publication_manifest.json) contains **no confirmed real Hugging Face dataset or collection URLs**. The presence of README files or owner-entered `external_access_verified: true` has never been sufficient evidence that judges can access the materials.

Official [Lexsi instructions](https://hackathon.lexsi.ai/) require public, **ungated model and dataset collections** and public/ungated individual repos, an under-500-word abstract, a write-up, and reproducible GitHub code/notebooks. Track 2a uses a benchmark and currently has no verified fine-tuned model to put into a model collection. **Do not invent a model repository or treat a gated original Tiny Aya repo as our own release.** Ask the organizers how a benchmark-only submission should handle this field.

## The actual safe publication sequence

1. Decide that the fictional research dataset may be published, verify rights and choose the final appropriate license (the owner must approve publication).
2. Use [the existing dataset publisher](TRACK2A_HF_PUBLICATION_GUIDE.md) to stage/check the original pinned 20-file archive, and **explicitly opt in** to publish from a private user environment. The publisher requires `HF_TOKEN` in the environment and rights/publication confirmation. **This separate verifier never publishes** and never asks for or prints a token.
3. Obtain the actual public dataset repository URL and an actual public **dataset collection** containing that repository, plus a genuinely relevant and allowed **model collection** (if the organizer clarifies what can be supplied for Track 2a).
4. Enter the genuine URLs into `docs/hf_publication_manifest.json`:
   - `dataset_url`: `https://huggingface.co/datasets/<namespace>/<name>`
   - `dataset_collection_url`: `https://huggingface.co/collections/<namespace>/<slug>`
   - `model_collection_url`: `https://huggingface.co/collections/<namespace>/<slug>`

   Keep every unverifiable flag `false` or `null` until the checks have actually succeeded. **Do not place any token in the manifest.**

5. Run the **network-free, read-only** default:

```bash
python -m scripts.verify_hf_collections
```

This validates URL format and tells you if a recent matching proof receipt exists; it does not make HTTP requests.

6. When all real links are in place, explicitly request **anonymous network verification** (requires `huggingface_hub` and Internet):

```bash
python -m pip install huggingface_hub
python -m scripts.verify_hf_collections \
  --verify-network \
  --output artifacts/hf_anonymous_access_receipt.json
```

The verifier uses `HfApi(token=False)` and **passes `token=False` to every request**. This matters: owner-authorized access is not proof that a judge with no license or token can inspect the release.

## What is independently fetched

- Both collection pages must be readable anonymously and be `private == False`.
- The model collection must contain at least one model repo; the dataset collection must contain the exact PolicyProof dataset repo. Repositories must have a full Git commit revision and be explicitly `private == False` and `gated == False`; unknown access status fails closed.
- Required dataset research files must be visible on the public repo at the **pinned repo commit**, then downloaded anonymously. Every required source file must match the dataset's publicly downloaded `provenance/SHA256SUMS.txt`.
- The public dataset card and scope must report the same declared dataset license, while independently proving **neither ownership nor permission to relicense**. Scope must affirm **48 saved original-base evaluations** and **72 unscored** challenge examples, no adapter and no completed human review, consistent with the actual files. The verifier checks the 48/72 data counts, unique IDs and unscored flags rather than merely trusting those numbers.
- The output contains the manifest SHA, exact collection and repo identifiers, pinned remote SHA values, observed time, checked source counts and explicit warnings that eligibility, ownership, relevance, training and submission remain unverified.

**This is public-access verification, not a scientific validation of model outputs or independent proof of the publisher's rights.** The model collection's relevance to the benchmark-only track remains an organizer judgment. The script does not validate the model's architecture, weights, or actual participation.

## Prevent misleading release status

`scripts.track2a_readiness` now deliberately ignores owner-entered publication booleans. It requires a separate `artifacts/hf_anonymous_access_receipt.json` generated by the explicit public-read verifier, matched to the exact current manifest SHA, with a verification timestamp no older than **72 hours**. A stale or mismatched receipt returns **not ready**. This is a local integrity check on a stored receipt, not a digitally signed attestation; re-run the anonymous network check immediately before submission. Do not upload private tokens, passwords, training archives or reviewers' unpublished feedback.

To check:

```bash
python -m scripts.track2a_readiness
python -m scripts.track2a_readiness --strict
```

The strict command exits nonzero when publication/eligibility prerequisites are missing. The regular command remains informational; neither command submits the official Lexsi form.

## Reproducibility and test scope

```bash
python -m pytest -q tests/test_verify_hf_collections.py tests/test_track2a_readiness.py
```

Offline tests use a **fake anonymous API** and synthetic temporary file data only. Those tests **do not demonstrate** that any real Hugging Face repository or collection was published. The verifier itself requires real URLs and makes no network requests unless `--verify-network` is supplied.

The existing project still needs official form submission, and training/paired evaluations are separate unfinished research tasks.
